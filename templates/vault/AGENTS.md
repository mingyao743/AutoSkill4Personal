# 项目写作约定

本文件给**编译器**读，描述这个项目的知识该怎么写。改它会影响后续所有自动编译。

## 语言与风格

- 正文用中文
- 页面标题用名词短语，不用问句（「zstd 多帧解压」而不是「怎么解多帧 zstd」）
- 一页讲一件事；讲不完就拆页，用 wikilink 连起来
- 代码片段必须带语言标记

## 什么该写

| 写 | 不写 |
|---|---|
| 踩过的坑与根因 | 「今天调了很久」这类过程 |
| 为什么选 A 不选 B | 复制粘贴的官方文档 |
| 能复现的步骤 | 没验证的猜测（要写就标 `[inferred]`） |
| 接口的真实行为（尤其与文档不符的） | 一次性的临时命令 |

## 页面结构

```markdown
---
title: 名词短语标题
summary: 一句话说清这页讲什么
tags: [主题, 技术栈]
category: concepts
confidence: 0.8
status: active
sources: [会话或链接]
---

## 是什么

## 为什么这样做

## 怎么做

## 踩过的坑
```

## 来源标记

| 标记 | 含义 |
|---|---|
| 无标记 | 实测验证过 |
| `[inferred]` 或 `（推断）` | 从上下文推的，没实测 |
| `[ambiguous]` 或 `（存疑）` | 有矛盾信息，未解决 |

**推断占比超过 70% 的页面发不出去**（门禁拦）。这是故意的——猜测不该进知识库。

## 引用

- 页内引用用 `[[页面名]]`，发布时会改写成平台链接
- 外部链接直接写 markdown 链接
- 引用代码位置用 `path/to/file.ts:42`

## 别做的事

- 不要把凭据、token、连接串写进正文（门禁会拦，且拦下时指出行号）
- 不要复制大段日志；留结论和关键几行
- 不要建「临时」「草稿」这类页；用 `_raw/` 快速记，等结论稳定再转正
