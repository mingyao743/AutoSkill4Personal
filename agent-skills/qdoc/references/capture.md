# 什么时候值得沉淀

## 自动触发（默认）

满 30 轮自动编译一次。但**不是所有轮次都值得写**——信号门会先筛：

| 信号 | 判定 | 例子 |
|---|---|---|
| 没有用户消息 | 不编译 | 只有工具输出 |
| 没有助手结论 | 不编译 | 只调了工具就结束 |
| 有工具调用 + 讨论 | **编译** | 排查问题、改代码、对比方案 |
| 纯检索 | 不编译 | 「这个文件里写了什么」 |
| 闲聊 | 不编译 | 「你好」「谢谢」 |
| 实质性讨论 | **编译** | 有取舍、有结论、有踩坑 |

## 手动触发

用户说「小q 沉淀」时**跳过 30 轮闸**，立刻编译当前会话。

`ow capture --plan` 可以先看会编译哪些窗口，不烧 token：

```
✓ 第 1–30 轮（30 轮 / 45210 字符）
   信号：substantive-discussion  工具调用 47 次
✗ 第 31–32 轮（2 轮 / 1200 字符）
   信号：short-chatter  工具调用 0 次
```

## 窗口怎么切

- 默认每 30 轮一个窗口
- 字符上限 12 万（超了按「用户消息优先 → 每轮最后一条助手回复 → 工具输出」顺序裁剪）
- 工具输出单条最多留 2000 字符（够看清结论，不留全量日志）

## 一轮到底怎么数

| 宿主 | 数什么 |
|---|---|
| dsh | `turn/end` 事件，排除 `reason.kind == "aborted"` 且无产出的 |
| pi | `message.role === "user"` 的消息 |

**坑**：dsh 把 `runtime-context` / `time-context` / `skill-catalog` 也存成 `role: "user"`。
必须按 `data.source.kind === "user"` 过滤，否则轮数虚高 3 倍（实测 17 条 → 6 轮）。
