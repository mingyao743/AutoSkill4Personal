# 从会话里抓什么

## 会话长什么样

你拿到的是一个窗口：连续 N 个用户轮次，含用户消息、助手回复、工具调用结果。

工具结果**已被截断到 2000 字符**。看到「原文 N 字符，已截断」就说明后面还有内容没给你——不要基于截断处猜测结论。

## 五个必看的位置

| 位置 | 找什么 |
|---|---|
| 用户的**第一句** | 真正想解决的问题。后面的追问常常跑偏 |
| **报错原文** | 精确的错误码与消息，是知识页最硬的证据 |
| **改了什么** | 从「报错」到「好了」之间动过的东西 |
| 用户的**纠正** | 「不对，应该是…」——这类句子含金量最高 |
| 最后的**结论句** | 「所以其实就是…」 |

## 反例：这些不是知识

```
用户：帮我看看这个函数
助手：（读文件、解释代码）
用户：好，谢谢
```

——没有结论、没有改动、没有新事实。跳过。

```
用户：报错了
助手：试试把 X 改成 Y
用户：好了
```

——**这个是知识**：症状（报错）、原因（X 不对）、改法（换成 Y）。虽然短，但可复用。

## 判断「可复用」的问法

问自己：**三个月后另一个人遇到同样情况，这页能帮他省时间吗？**

- 能 → 写
- 只能帮到「当时那个具体任务」→ 不写
- 不确定 → 写，但 `base_confidence` 给低一点，`lifecycle: draft`

## 时间性内容要标时间

数字会过时：版本号、星数、价格、限制值。

- ✅ 「qdoc MCP 有 10 个工具（2026-11-13 实测）」
- ❌ 「qdoc MCP 有 10 个工具」

不标时间的数字读起来永远为真，这是知识库最常见的腐坏方式。
