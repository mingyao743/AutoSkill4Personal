# 知识库的三层结构

从上游 obsidian-wiki 的 llm-wiki 模式迁移，按 qdoc 的实际情况简化。

## 三层

| 层 | 是什么 | 谁能改 |
|---|---|---|
| 原始层 `.qdoc/_raw/` | 会话快照、抓取的网页、丢进来的文件 | 只追加，不改 |
| 知识层 `.qdoc/concepts/` 等 | 从原始层提炼出的页面 | 编译器写，人可以改 |
| 规则层 `.qdoc/AGENTS.md` + 本技能 | 这个库该怎么写 | 人写，编译器读 |

**为什么分三层**：知识页会被人改、被重写、被废弃，但「当时到底发生了什么」不能丢。原始层留着，才能回答「这页是依据什么写的」。

## 一页的寿命

```
draft  →  active  →  archived
             ↓
         disputed
```

| 状态 | 含义 | 会不会发布 |
|---|---|---|
| `draft` | 刚生成，还没人看过 | 会（但置信度低会被拦） |
| `active` | 可用 | 会 |
| `archived` | 已过时，被别的页取代 | 不会 |
| `disputed` | 有争议，证据矛盾 | 不会 |

归档不删除。理由：删了之后，引用过它的地方就变成死链，而且没人知道「这里曾经有内容」。

## 置信度怎么给

| 情况 | base_confidence |
|---|---|
| 全部是会话里明确说过的 | 0.85–0.95 |
| 有少量推断补全 | 0.65–0.85 |
| 大半是推断 | 0.45–0.65 |
| 证据薄、只有一处提及 | <0.45（发布门禁会拦） |

门禁阈值是 0.45。低于这个值不发布，但仍留在本地——也许以后有更多证据能补上。

## 与上游的差别

| 上游 | 这里 | 为什么 |
|---|---|---|
| `category:` 字段 + 目录双写 | 只靠目录 | 两处写同一个事实必然漂移 |
| `aliases` / `relationships` 块 | 暂不做 | qdoc 平台没有反链查询，做了也没人用 |
| `tier` 重要度分级 | 不做 | 页面少的时候分级没意义 |
| `snapshots` 快照链接 | 不做 | 平台没有附件概念 |
| `provenance:` 比例块 | 保留（可选） | 有它才能一眼看出哪页是推测堆出来的 |
| 严格的 `## Sources` 末节 | 改为 meta 注释 | 平台正文里不需要这一节，注释更干净 |
