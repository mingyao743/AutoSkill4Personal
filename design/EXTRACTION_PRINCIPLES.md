# 抽取原则 Spec：什么内容够格成为知识原子

> 状态：v0.2（P0/P1 已落地实现：抽取 prompt 升级 + G4 机械拒 + schema grounding 字段；P1 review 分级随 /kb-review 实现跟进；P2 否定/转折点前置检索未做）。
> 定位：本文件是抽取准入标准的**单一权威定义**。上游约束 `lib/prompt.ts` 的抽取规则、下游约束 review 判定（/kb-review pass/降级/废弃）与组装合并。
> 与既有文档的关系：触发体系（何时抽）见 KNOWLEDGE_EXTRACTION_PLAN_V2.md §2；本文只管"什么够格抽"。结构约束（抽成什么形状）见 atom.schema.json + SLICE_CATALOG.json。

---

## 一、三条判定轴

每条候选内容过三轴，任一轴为零则不入池：

| 轴 | 定义 | 反例（轴=0） |
|---|---|---|
| **稀缺性** | 不在模型参数知识里、不可随取随再生 | "GRPO 是什么"的回答；通用最佳实践（"该加测试"） |
| **验证性** | 被现实验证过：执行结果、用户确认、文档依据 | 逻辑自洽但未检验的推测 |
| **复现性** | 未来任务场景会再次遇到 | 纯会话一次性事务（这份文件、这轮日志本身） |

**专业感不是验证性。** 推理流畅、术语准确、结构漂亮都不构成证据链。LLM 恰好最擅长生产"听起来专业"的内容，此类是最大污染源。

---

## 二、价值来源优先级（总纲）

> 对话的高价值几乎全部产生于**人机摩擦点**与**现实检验点**；模型单独流畅生成的部分，价值趋近于零。

```
P0  人 → 模型（否定/修正/领域知识/决策理由）      ← 价值最高
P1  世界 → 模型（执行验证/预期违背/观测归纳）
P2  文档 → 模型（项目口径的索引化）              ← 可抽，但注明仅为文档映射
P3  模型 → 独立生成（无接地的推测）               ← 默认不抽
```

抽取引擎读日志时天然偏好抽 LLM 自己写得漂亮的部分，此倾向必须被以下规则主动压制。

---

## 三、六类高价值内容（正向清单）

### C1 人对模型的否定与修正 【P0】

- **内容**：用户纠正模型的假设/口径/做法，及其理由。隐性知识（偏好、约定、品味、行业惯例）只在此瞬间显形。
- **抽取要求**：必须保留**修正前后的对照**（错在哪、改成什么），单存正确版损失全部价值。
- **对话信号**：否定词、转折、坚持重述（"不对""不是这个意思""反了"）。

### C2 决策及其理由 【P0】

- **内容**：在多个备选项间做了取舍，含 rejected alternatives 及其代价。
- **抽取要求**：结论孤立无价值；必须含被否路径与理由。无备选对比的单一结论不抽。

### C3 被验证过的经验性事实 【P1】

- **内容**：跑了命令、看到结果、复测通过——世界反馈型知识，环境绑定。
- **抽取要求**：标注 grounding=执行验证；写明 context 先验（§六）。

### C4 人的领域知识外溢 【P0】

- **内容**：用户解释业务、定义口径、给出判断标准（"这种算误杀，那种不算"）。
- **抽取要求**：多轮拉扯后**收敛的最终表述**优先于任何单轮表述——反复打磨的精度高于初版。

### C5 预期违背（惊讶时刻）【P1】

- **内容**：预期 X 实际 Y：OOM 出现在"不该"的阶段、操作与效果反向。
- **抽取要求**：归因必须已验证（复现/修复生效）才可作 05 类 root_cause；未验证只可标注为假设（§五 G4）。

### C6 会话间复现的隐性上下文 【P1】

- **内容**：用户环境、命名约定、雷区。单会话是噪音，跨会话重复即值得固化。
- **抽取要求**：只在多源（≥2 个 session/sources）佐证时升级为 published。

## 四、负面清单（不入池）

1. **参数知识复述**：问答双方都未注入会话特异性信息。
2. **正确但通用的建议**：无环境/项目绑定，换个会话同样成立=无复用增量。
3. **未验证的推测**：见 §五 G4。
4. **易逝性中间态**：文件内容、单轮日志、执行流水，除非凝结为教训。
5. **闲聊/简单问答/纯环境检查**（沿用现有 prompt 规则 7）。
6. **礼貌性与脚手架性对话**：确认、过渡、格式调整。

---

## 五、Grounding 分级（可机械推导，不依赖 LLM 自报）

LLM 抽取时自报 grounding ∈ {G1, G2, G3, G4}（写入原子字段）；机械校验兜底：**msg_range 区间内既无 toolResult 又无 user 消息 → 直接拒绝入池**（双保险：LLM 自报 G4 也拒）。区间无法定位时保守放行交人工。已实现于 `lib/extract-core.ts` isMechanicalG4 + `lib/validate.ts` 枚举校验。

| 级别 | 判据 | 准入 | review 强度 |
|---|---|---|---|
| G1 执行验证 | 区间含 toolResult 且结论与结果直接对应（复测通过更强） | ✅ | 快速通道 |
| G2 工具观测 | 区间含 toolResult（读文件/日志/指标后归纳） | ✅ | 常规 |
| G3 文档依据 | 区间为对项目文档/代码的读取与复述 | ✅（标注为索引型） | 常规 |
| G4 纯生成 | 区间无任何 toolResult，且非用户陈述（如 msg_range=[x,x] 单条 assistant 消息） | ⚠️ 默认不抽；确有 P0 价值（C1/C2/C4）时入池并强制人工 review，05 类必须显式标注"假设" | 强制 |

**confidence 解释权收窄**：confidence 只衡量"抽取动作的把握"，不衡量知识真伪。真伪由 grounding 分级 + review 承担。LLM 自评 0.9 的 G4 内容不因 confidence 高而豁免 review。

## 六、Context 先验（抽取时强制，写入既有先验族字段）

先验族字段 = 01 `boundary` / 02 `prerequisites` / 04 `applicable_conditions` / 05 `scenario`（语义统一为"本知识成立的前提"）。

- **R1**：环境/版本/机器绑定型知识（02 类 SOP 几乎全部），**必须**把限定写入先验字段。先验写不出来的知识默认按普适处理并接受 review 质询。
- **R2**：先验宁缺毋滥——无证据不编造（"适用于大多数 Linux 系统"式万金油假先验比缺失更糟）。
- **R3**：content 改写去语境化时，环境限定词不是噪音，必须迁移到先验字段而不是删除。

---

## 七、权重规则（抽取与 review 双侧适用）

1. **用户消息加权**：user 消息及其紧邻上下文是 C1/C2/C4 的发源地，优先扫描。
2. **否定/转折点定位**：检索否定词、转折、重述，向前后各扩展一个语义单元作为候选区间。
3. **验证段保护**：结论 + 佐证它的 toolResult 应落在同一 msg_range，区间只指向结论消息（如 [x,x] 单 assistant 消息）视为 G4 嫌疑。
4. **收敛版本优先**：同一口径多轮演化时，抽最终收敛表述；中间版本丢弃（不靠 superseded_by，抽取时即取终版）。

## 附：一页速查

```
够格 = 稀缺 × 验证 × 复现 三轴全过
优先抽：人修正模型、决策+被否路径、执行验证事实、人口径、预期违背
默认不抽：参数复述、通用建议、未验证推测、流水账
先验：环境绑定必须写前提，编不出前提按普适质询
grounding：G1/G2/G3 入池，G4 默认拒（人环价值除外）
信号：盯用户消息、否定转折、验证前后段；抽最终收敛版
```
