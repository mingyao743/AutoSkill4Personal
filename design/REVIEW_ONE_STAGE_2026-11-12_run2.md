### 三项已拍板（2026-11-12）并已实现

**① 特化字段缺失 → 降级入库 + 记待补。** 只缺 `concept_name` / `definition` / `problem` 这类类型必填字段时不再拒：用卡片**自己的** `title`（名字类）和 `body`（内容类）补位，补过的字段名记进 `pending_fields` 表示"推导来的、不是模型申报的"，再重新校验入库。其他校验错误（接地、`msg_range` 非法、敏感信息）**一律照拒**。
> 修正我先前的说法：我在选项里写"按通用 `spec` 存"，查了 `DOC_TYPE_SPEC` 才发现 **8 个类型全都有必填字段**，其中 5 个都要 `concept_name`+`definition`，没有零要求的兜底类型。所以保留原 `doc_type` 补位是唯一可行做法。
> 按本轮数据，这一改可回收 **6 张**（被拒 18 张里的三分之一）。

**② quote 逐字校验 → 不做硬闸门，打标记。** 落库时写 `quote_verified: false`，交人确认环节判断。理由就是那唯一一例"注释说默认 false、代码是 `if (config.enabled === false) return`"——硬闸门会把这类**发现代码与注释不一致**的高价值卡和真摘抄一起杀掉。
> 校验的比对对象是**模型实际看到的压缩文本**，不是原始会话日志。这点很关键：原始日志里 tool-call 的 `arguments` 是 JSON 字符串、换行被转义成字面量 `\n`，拿它做子串匹配会把合法引用误判成编造——我自己第一版校验就这么误判了 11/38，查出来才改对。

**③ `sop` / `template` / `rubric` 仍为 0 → 换操作型会话再验一轮。但我给你的前提是错的，结论要改。**

我在提这条时说"本会话是设计讨论型，可能本来就没有可复现流程类知识"——**验证跑推翻了这句**。同一条会话只跑前 3 批，就出了一张 P0 `sop` 卡：

> **[sop] 检测流程定稿：拆解→机械闸→一次判定**（P0，`autoskill-pipeline`）
> `step`：1) 拆解成单点 → 2) 机械闸门（msg_range 无 user 消息/工具结果/sources 即拒） → 3) 一次判定五字段（去向+类型+理由+失效+关系） → 4) 分写三处（技能正文/资料库/运行账），拒收留账

18 批全跑那轮**没有这张卡**，被拒原因里也没有"特化字段缺失: step"——说明它压根没被提出过，不是被闸门拦掉的。

**所以真问题不是"某类型抽不出来"，而是 run-to-run 方差**：同一条会话两次跑出的卡片集合不一样（两轮输入也确实不同——验证跑带了元数据过滤，522 行 → 500 行，批次边界随之移动）。这直接说明**单轮的"类型分布"不能当验收结论用**，而探针召回（本轮 5/5）比它可靠得多。

**因此新增一个待拍板项：方差要不要治？** 选项：同批多跑一次取并集（贵一倍）／降低采样随机性／把验收口径从"类型分布"换成"扩到 10–15 个探针的召回率"／先不治、只把类型分布从验收标准里去掉。我倾向第三个 + 第四个组合：类型分布降级为观测指标，验收只看探针召回。

数据层因此新增 **2 个可选字段**：`quote_verified`（bool）、`pending_fields`（string[]）。都走 `KnowledgeAtom` 的索引签名，旧卡片与旧读取方不受影响——加上之前的 `title` / `value_tier` / `source_quote`，一共 5 个新增可选字段。
