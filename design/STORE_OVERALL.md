# "存"的整体方案（STORE_OVERALL）

> 状态：整理稿 · 2026-11-11（汇总 STORE_PLAN / TRIGGER_PLAN / SKILL_COMPILER / ARTIFACT_CAPTURE 四份方案 + 平台接入讨论）
> 术语：全文统一新叫法——知识卡片 / 一段式抽取 / 准入规则 / 短效知识 / 历史记录；旧名对照见名词表。
> **决议（2026-11-11，三项，均待实现）**：① 抽取改为**一段式**（一次调用做完检测+提炼+定性+drop 记账，详见 `ONE_STAGE_EXTRACT.md`）；② 技能生成改为**选材器 + 契约自研、正文生成外包给 create-skill**；③ 文档线按**信号强度分档**决定直接存还是问用户。现行代码仍是两段式（`lib/trigger-scan.ts` → `lib/knowledge-extract.ts`），迁移路径见 ONE_STAGE_EXTRACT §六。
> 一句话：**把聊天里值得留的话自动收进本地知识池，池子里的东西按规矩分类、攒够了写成能直接照做的技能和文档；人只在"成品"上点头，从不逐条审。**
> 范围：只讲"存"。"评"（用得怎么样、要不要退役）是下一阶段。

## 〇、全景一张图

```
 对话消息                              大文档 / 被引用的资料
   │                                        │
   ├─① 一段式抽取（一批一次 LLM 调用）      └─ 文档线（§二入口⑤，详见§五）
   │      检测有没有货 → 写成卡片 →              结构信号触发，零 LLM 成本，不扫消息：
   │      定性（类型/失效/损失）→                写了文档 / 长结构化输出 / 被引用
   │      记 drop（看了没抽 + 理由）             ⑴ 整份收编 → artifacts/（缩减/切片/blob）
   │      ↓ 知识卡片 + drop 账                   ⑵ 抽取段：文档内容 → 可复用知识卡片
   │                                            （与①同一条流水线，判重后抽增量）
   │                                            落库 ↓ ＋ 一张 index 登记卡 ↓
   ├─② 准入规则 + 判型：该不该存 / 是什么类型 / 存成什么
   │      ↓
   │   ┌─────────────── 两条线在这里汇合 ───────────────┐
   │   知识卡片库 atoms.jsonl（唯一事实源）──按类型分流，三种去向：
   │   └───────────────────────────────────────────────┘
   │        │
   │        ├─ instruction 6 类（sop/spec/template/postmortem/convention/rubric）
   │        │       ↓
   ├─③ 技能线：同一主题的卡片攒够门槛（≥5 张、来自 ≥2 个会话）
   │        │       → 选材器 + 契约（自研）→ create-skill 生成（外包）
   │        │       → 规则校验 + 路由自测 → SKILL.md + references/
   │        ├─ case（reference）→ 技能附录（带溯源；正文预算装不下就放这里）
   │        └─ index / data → 资料层（只存档不进技能；检索口是缺口，见§七）
   │
   └─④ 人确认成品（技能草稿 / 摘要卡 / 文档确认卡）→ 平台发布
```

**为什么入口分两条，汇合之后却只有一条路**——文档线不并入主管线的三个硬理由：

1. **原料不同**：主管线吃"话"，为控成本要压缩——助手中间消息只留首尾各 500 字、工具输出只留要点；而**写进文件的文档根本不在对话流里**，主管线看不到它。文档的价值恰恰是结构（标题树 / 表格 / 占位符），压缩视图装不下
2. **触发经济学相反**：消息靠"宁可多看"（LLM 全量过目，有 token 成本）；文档靠"形状吻合才收"（零成本结构信号）。硬并成一条，要么每轮烧 token 扫文档，要么退回刚证明失败的"正则召回"
3. **产物不同**：一边是小卡片（攒着编译技能），一边是整份文件（哈希去重、版本 supersedes、独立的文档确认卡）

但"并列"只发生在入口：**同一个卡片库、同一套准入规则（含 PII 拦截）、同一道人工确认、同一个发布口**——过了汇合点，系统里没有第二条线。

## 一、什么东西值得存（准入判据）

**三问，任一答"否"就不存**：

1. **可再生吗**——不存它，以后能不能低成本重新得到？
2. **会改变动作吗**——以后会不会影响某个做法或判断？
3. **说得出损失吗**——能不能写出一句"不存会损失什么"？

**价值从哪来**（按优先级）：

| 级别 | 来源 | 例子 |
|---|---|---|
| P0 | 人纠正模型 | "不对，反了""这种才算误杀"——隐性偏好只在这一刻显形 |
| P0 | 决策 + 被否方案 | 选了 A 没选 B，为什么 B 不行（孤立结论不抽） |
| P1 | 现实验证 | 跑了命令、看到结果、复测通过 |
| P1 | 意外 | 预期 X 实际 Y（OOM 出现在不该出现的阶段） |
| P2 | 文档口径 | 项目文档里写的规矩（注明是文档映射） |
| P3 | 模型自说自话 | **默认不抽**——流畅、专业、漂亮都不是证据 |

**不存的**：模型背书复述、换个会话同样成立的通用建议、未验证的猜测、执行流水账、寒暄和格式调整。

## 二、怎么触发（四条入口 + 一条并列文档线）

| 入口 | 什么时候跑 | 干什么 | 产出信任级 |
|---|---|---|---|
| ① 一段式抽取（主路） | 每轮检查，**待审 ≥30 条 或 ≥12k token** 即成批（不看时间） | 一批一次调用：检测 + 出卡片 + 定性 + 记 drop | signal（最信任，优先进技能） |
| ② 任务收尾 | 任务完成 / 退出 / commit / 空闲 | 只补"没覆盖到的尾巴"，不重扫 | harvest |
| ③ 压缩抢救（兜底） | 对话太长系统压缩时 | 只捞别人没捞过的缺口，产物先**隔离** | rescue（隔离，凭摘要卡转正） |
| ④ 手动 | agent 声明（capture_knowledge）/ 人工回填 | 单条声明走同一套准入规则，没有免检 | backfill |
| ⑤ 文档线（与①并列） | 每轮零成本扫描结构信号 | 大文档、被引用的资料 → 整份留存 | 见第五节 |

**背景**：改造前 46% 的知识卡片靠压缩抢救、17 个技能 100% 由它构成，主路反了。这套设计让"日常摩擦"重新成为主供给，抢救降回兜底。

### 召回不靠正则（这条铁规矩在一段式下照样成立）

实测教训：855 条消息的会话里，正则只命中 3% 的用户消息，**7 条实质反馈全部漏掉**（"还是不行""对的，但是…"——真正有价值的反馈往往不带否定词）。

所以规则反过来：**每条消息一辈子至少被 LLM 审一次**，审不完留到下一轮，绝不算已覆盖。这样覆盖率可审计、可承诺 100%。

一段式改造后，"看一眼"和"抽成卡"是同一次调用；**覆盖率由代码记账**（喂进批次的消息即视为已审），不依赖模型自报。批次按会话轮次对齐、不切开一轮，并带上一批最后 1 轮作只读上下文，防止"第 12 条的方案 + 第 31 条的纠正"被窗口切散（详见 ONE_STAGE_EXTRACT §二）。

**现状（2026-11-11）**：召回链路已经零正则，连设计预留的"插队/热区"也不实现（纯延迟优化，覆盖率承诺下不影响召回）；正则现役岗位只剩准入规则拦敏感信息（API key / 手机号 / 邮箱——确定性模式匹配，正则擅长的活）。

### 喂给模型什么（压缩规则；旧规则实测压到原文 24%–35%，放宽命令行与 stderr 后实测 **38.9%**）

| 消息 | 喂给模型的 | 理由 |
|---|---|---|
| 用户消息 | 全文 | P0 主产地，只占 0.4% 体积 |
| 助手消息 | 最终回复全文 + 中间消息首尾各 500 字 | 平均 141 字，基本等于不截断 |
| **工具参数（命令行）** | **完整命令行，上限 2000 字**；超限整条透传不压 | sop 卡的核心是"到底跑了什么"，截到 80 字就不可复现。2000 是实测定值：143 条命令中位 579 字、P90 2477 字，600 会截掉一半 |
| **工具参数（写文件的正文）** | 上限 600 字，超限只标注、**不触发透传** | `write`/`edit` 的 content 是文件正文不是命令，截断不影响可复现性。不分档实测有 19% 的消息被无谓透传 |
| **工具参数（结构化 JSON/YAML）** | 键名 + 前 80 字 | 重复结构化参数是体积大头、价值低 |
| **工具结果（失败/有 stderr）** | **stderr、报错行全文（上限 800 字）** + 首行 + 长度 | postmortem 卡的"现象"必须是报错原文，不能是转述 |
| 工具结果（成功无 stderr） | 首行 + 成功标记 + 长度 | stdout 是体积大头、价值低 |

**修订原则（2026-11-11）**：放宽的都是**小体积高价值**部分（命令行、stderr），继续压的都是**大体积低价值**部分（stdout、重复 JSON）。这么改之后，压缩视图对 P0（人说的话）本来就无损、对 P1（现实验证）也基本无损——这是一段式能成立的前提。若实测 P1 卡片逐字接地合格率 <90%，再开"按需回读原文"（ONE_STAGE_EXTRACT §3.4）。

### 成本与护栏（两段式实测基线：855 条消息约 79k 入 / 156k 出；一段式目标砍到 50–60%，沿用推理模型前提下的估算）

- **增量扫描**：默认只扫新消息，每条一辈子只看一次；全量回扫必须显式命令（`--backfill`），防止新用户第一晚烧 200k token
- 预算：单次 20k / 常规会话 80k / 回扫 300k / 单日 500k，超了**停在未审**（不丢、下轮继续），降级时记录在案
- **模型档位沿用推理模型，不降档**（2026-11-11 决议）：两段式实测输出 156k 是输入的 2 倍，成本主因是推理 token——但**砍掉的是"独立扫描那一趟"，不是档位**。一段式之后同一批内容只推理一遍，浪费从结构上消失；再降档动的是抽取质量，而抽取质量是这条管线唯一的产出。若成本验收不达标，杠杆顺序是 批次体积 → prompt 缓存 → 最后才是档位
- **节流只看量不看时间**（2026-11-11 决议，取消"距上次 ≥10 分钟"）：跑完一批水位前移、待审归零，30 条门槛本身就防抖；不满 30 条的尾巴由入口②（完成/退出/commit/空闲）兜底
- 后台调用只花 API 额度，**不占对话上下文窗口**

## 三、落库流水线：定性 → 准入 → 分流（四个入口共用一条）

```
① 一段式抽取  检测 + 拆解 + 定性 + drop 记账，一次 LLM 调用   [LLM]
② 准入规则    来源 / 接地 / 敏感信息 / 类型合法              [代码，零 token]
③ 落库        类型→去向查表，自动分流                        [代码]
④ 复核        只有资料类进人工队列                           [人]
```

逻辑四步，实现上是**一次 LLM 调用 + 两次规则校验**（准入 + 分流）。**四个入口共用同一条流水线**（改造前是三扇门三套规矩：45% 知识卡片没来源、41% 类型名是模型自造的）。

**① 的输出契约有两处硬约束**（防退化成摘要，详见 ONE_STAGE_EXTRACT §四）：

- 卡片可以为空，但 **drop 账必须有**——"看了没抽 + 理由 + 哪条判定轴为零"要留痕，否则漏检永远是盲区
- `value` 字段**不允许填 P3**（模型自说自话）：P3 一律进 drop。把"P3 默认不抽"从建议变成契约

### 8 个类型（存什么由类型决定；去向是代码查表，产线归属见右列）

| 类型 | 通俗 | 去向（代码 keepAs 已实现） | 产线 |
|---|---|---|---|
| sop | 按什么顺序做（含排障） | 技能正文 | 技能线 |
| spec | 什么算对、必须遵守什么 | 技能正文 | 技能线为主；外部规范整份被引用时，被引段落另走文档线切片 |
| template | 填空就能用 | 技能正文 | 都可能：骨架进技能；"以后都按这个格式"的整份模板走文档线 |
| postmortem | 上次为什么炸 | 技能正文 | 都可能：卡片只留"现象→根因→处置"；整份复盘报告走文档线 |
| convention | 这台机器/这个项目的规矩 | 技能正文（必须写失效条件） | 技能线 |
| rubric | 怎么打分 | 技能正文 | 技能线 |
| case | 照着它做（含客户资料） | 技能附录（reference，带溯源） | 都可能：摘要卡进附录；原始资料整份走文档线（blob 须脱敏 + 人确认） |
| index | 东西在哪 | 资料层（data） | 永不进技能正文；文档线的登记卡就是 index |

**归纳**：技能线吃 6 种 instruction 类卡片；case / index 永不进技能正文；文档线两段产出——收编段落整份文件 + 一张 index 登记卡，抽取段（§五）判重后产可复用知识卡片、与主管线产物同走技能线。分界一句话：**要"以后照着做"的部分压成卡片，值得整份留档的原件走文档线收编。**

### 成品形态对照（四种常见样子，路通不通）

| 成品形态 | 原料进卡（①→②） | 成品成形（③技能线 / 文档线） | 判定 |
|---|---|---|---|
| 流程 SOP | sop 型专属户口 | 技能正文（body 预算最大 8000） | ✅ 全通，最强路径 |
| 问题-方案笔记 | 排错/故障/踩坑→postmortem；选型→spec（rationale/rejected 装"替代方案"） | 技能线重组为排障段、决策记录（Q&A 表面形态不保留，内容都在） | ✅ 内容通 |
| 对比矩阵 | 散落多轮→多张 spec/case 卡；贴现成表→长结构化信号→文档线收编 | **跨卡合表原本没设计** → 已补进选材器职责（见下） | ⚠️ 半通，已有对策 |
| 原理简报 | 8 类型无户口；通用原理被"可再生吗"合理拒绝；架构理由落 spec.rationale | 对话里讲清、没写成文档的**项目私有机制解释**直接漏 | ❌ 真缺口（§十#8） |

选材器补一条职责：**同类多卡聚合**——选型对比类合成对比矩阵，排障类合成排障清单（已写入 §四 流水线②，并同步进 SKILL_COMPILER 决议）。

### 准入规则（违反直接拒，被拒的进 errors.log 可捞回）

- 没有来源 → 拒
- 所引区间里既没有工具结果也没有用户的话（模型纯编）→ 拒
- 敏感信息：密钥一律拦；手机号/邮箱/证件号对资料和案例硬拦（客户资料必须先脱敏）
- "不存会损失什么"写不满 8 个字 → 拒
- 类型必填字段缺 → 拒
- **正文与引用原文重合度 ≥60%（阈值待定）→ 拒**：那是摘抄不是提炼。零成本代码检查，反摘要的常驻闸门（借鉴 billion-context 的 net-benefit gate：摘要不比原文小就拒）
- **把历史写成祈使句 → 拒或退回重写**：卡片会进技能正文、被未来的 agent 读到。"当时定的是先 A 再 B" 可以，"要先 A 再 B" 不行——否则历史指令会被当成当前任务执行

每张卡还强制带：**来源**（哪条消息）、**接地等级**（G1 执行验证 / G2 工具观测 / G3 文档依据 / G4 纯生成，G4 默认拒）、**失效条件**（规矩类和索引类必填——"这台机器的规矩"总会过期的）。

## 四、知识卡片怎么变成 skill（选材器 + 契约自研，正文生成外包，proposed）

改造前的真相：41 个技能里 40 个描述是模板句、**3 周只有 3 个被加载过**——因为打包器只是"排版"，没有"编译"。

**2026-11-11 决议：正文生成外包给 `create-skill`，选材和契约必须自研。** 理由：技能不被加载等于白做，而"会不会被加载"由 description 和选材决定，这两样恰恰是通用生成器不知道的东西——它不知道哪些卡是短效的、哪些跨会话复现过、这个主题的正文预算是多少。外包能省掉的是最机械的"把卡片组织成 Markdown"，省不掉的是判断。

```
① 就绪门    一个主题攒够 ≥5 张卡、来自 ≥2 个会话才值得编译      [自研·代码]
             └ 整个主题都是短效知识 → 转历史记录，不编译
② 选材器    排序：能不能照做 × 跨会话出现过几次 × 新鲜度 − 短效表述  [自研·代码]
             正文预算按类型 2000–8000 字，装不下的进附录
             同类多卡聚合：选型对比类 → 对比矩阵；排障类 → 排障清单
③ 契约      交给生成器的硬约束（不可协商）：                    [自研·代码]
             description 60–300 字且含 ≥3 个触发短语
             禁模板句式（"领域知识库""由 AutoSkill 生成""涉及…时加载"）
             正文分节 / 引用闭合 / 不得写短效表述 / 长度上限
             **历史引用不得写成祈使句**（"当时定的是…"，不是"要…"）
④ 生成      调 create-skill：传 技能描述 + 选中的卡片 + 契约      [外包]
⑤ 规则校验  结构 / 无元数据 / 无短效表述 / 长度 / 引用闭合（零成本） [自研·代码]
⑥ 路由自测  正样本 ≥4/5、负样本误命中 ≤1/3；                    [自研]
             不过就带原因重写，两次仍不过 → 禁止发布
⑦ 质量关卡  （可选）删除测试：删掉这句话，还照做得了吗
⑧ 落盘      只写提案，由统一写入者落盘；agent 精修过的技能只提案不覆盖
```

**为什么⑤⑥不能省**：外包生成最大的风险不是格式错，是 description 写得太泛——技能装了却永远不被加载，这正是改造前 41 个技能的死法。规则校验和路由自测是把"能不能被正确命中"变成可测指标的惟一手段。

**正文怎么写（最小绑定原则）**：允许补世界知识，但每句都要过**删除测试**——删掉它，某条经验会变得看不懂/做不了/分不清适不适用 → 写；只是多点背景知识 → 不写。技能不是教材，是经验的使用说明书。

**短效知识怎么办**：不删除也不进技能，转成 `<主题名>-current-state.md` 历史记录（可查、可检索、带失效日期）。主题里以后攒出真能照做的内容，会自动"毕业"重新获得编译资格。

## 五、文档线：整份资料的存法（ARTIFACT v2，proposed）

触发 + 抽取这条管线天生只能产"关于文档的判断"，产不出"文档本身"——一份 3000 字方案在扫描压缩时被压成首尾 500 字，结构在入口就丢了。所以单开一条并列入口，靠**结构信号**（零 LLM 成本）触发：

| 信号 | 例子 |
|---|---|
| 写了文档 | write/edit 落在 docs/design/templates/ 或 .md/.docx/.xlsx，内容 >1500 字 |
| 长结构化输出 | 单条回复 >2500 字，有标题/表格/代码块 |
| 用户粘贴大段 | 单条 >1500 字且带结构 |
| 明确意图 | "生成一份""做成模板""以后都按这个格式" |
| **被引用** | 结论里引用了某文件某段——**读本身不算信号，被引用才算** |

**信号分档（2026-11-11 决议：不是所有触发都问用户）**：先斩后奏会在 `artifacts/` 堆没人看的垃圾，先奏后斩会漏（当时说不要，三个月后原文已不在上下文）且打断心流。按信号强度分档：

| 档 | 信号 | 动作 |
|---|---|---|
| 强 | 明确意图（"生成一份""做成模板""以后都按这个格式"） | **直接存 + 事后告知**，不问 |
| 中 | 写了文档 / 长结构化输出 / 粘贴大段 | **进批量确认卡**，空闲时一次性问（不在任务中途单独问） |
| 弱 | 只是读了文件、短回复、无引用的抓取 | **不动**（可再生，准入三问第一问就拒） |

三种存法（判断顺序：能识别结构→缩减；有引用→切片；否则不存）：

| 形态 | 适用 | 存什么 |
|---|---|---|
| **结构化缩减** | 模板/方案/报告（原文 10–30%） | 标题树 + 占位符 + 关键决策，删示例和寒暄 |
| **切片** | 读到的规范/事实（每条 ≤200 字） | 被引用的那一段 + 出处 + 抓取日期 |
| **原文 blob** | 不可重获又没法结构化的（客户原始表格、扫描件） | 兜底，必须脱敏 + 人确认 |

存 `knowledge/artifacts/`（按内容哈希命名，天然去重）+ 知识卡片里一条索引。同一文档改版 → 新版本标记 supersedes，旧版标废弃。

### 收编之后：抽取段（2026-11-11 新增，proposed）

收编解决"文档本身不丢"，抽取段解决"埋在文档里的知识不漏"——主管线只扫对话消息，文档里的可复用知识（"部署前先跑 X""参数别超 Y"）如果对话里没说过，永远变不成卡片。价值表的 P2"文档口径"和接地 G3"文档依据"本来就为它留着位置，这一段是把管线接上：

- **怎么抽**：复用主管线同一条流水线（LLM 判型 → 准入规则 → 落库）；证据起点 = 文档路径 + 哈希（不是消息区间）；产物是 8 类型知识卡片，照常进技能线
- **只抽增量**：自写文档的知识大多已从对话里抽过（文档是从对话里长出来的），先判重再抽；**外部被引用的资料价值最高**——那些知识从没进过对话
- **blob 不抽**：客户原始资料只收编不知识化，抽了是 PII 风险
- **登记卡保留**：一份文档一张 index 登记卡（路径 + 哈希 + supersedes 版本链 + 失效条件 + **内容一句话**）。它不是知识卡，是 artifact 在唯一事实源里的户口——版本链挂它、去重锚它、抽出 0 张卡的纯资料文档靠它可见。抽取卡答"文档里有什么可复用"，登记卡答"这份资料在哪、什么版本、讲的是什么事"
- **内容一句话是必填不是可选**：记"它讲了什么"，不是"它在哪"。反例"探针脚本在 /path/x.py"；正例"x.py：测 n-gram 基线、生成质量、长程依赖、位置敏感性"。理由：§七 那个"资料层只写不读"的缺口，将来检索靠的是**内容相关**，不是猜路径
- **零人工不变**：抽取卡走知识卡片层（不过人工）——原料已过文档确认卡；抽取段的触发时机见§十第 7 条

## 八、最后一步：存到平台（qdoc.chat/mcp）

三条硬边界（会话内已讨论一致，**方案文档未落盘**）：

1. **知识卡片永不出端**——知识卡片是私有的，只发布渲染后的成品（技能/文档）
2. **平台是唯一共享面**——发布后"用"也走平台，本地只做缓存
3. **改动两阶段**——先 `prepare_change`：平台返回"改了什么 + 影响谁 + 现在的使用成绩 + 风险"，人确认后才 `commit_change` 落库（高风险改动如删除、描述变更，强制去网页确认）

已查证的现状：qdoc MCP 支持 documents/skills 双开关和多宿主接入，但公网 `POST /mcp` 当时返回 405，传输层未通，是接入第一号待查证项。

## 十一、架构复盘：哪些是必要复杂度，哪些是过度设计（2026-11-11）

这一节记录一次完整的"是不是设计过头了"的复盘，包括被 challenge 的方案、逐项判定、以及最后砍掉/保留的理由。**结论不是"原设计全对"，也不是"简化方案全对"。**

### 被 challenge 的简化方案

> ① 每 30 条新消息调一次 LLM，总结有价值的知识卡片；② 定期扫卡片，有价值的调 `create-skill` 传描述 + 参考卡片生成技能；③ 有价值的文档先问用户要不要整理保存。

### 判定结果

| 简化点 | 判定 | 依据 |
|---|---|---|
| 合并两段抽取为一段 | ✅ **采纳** | 独立扫描的实测账单是入 79k / **出 156k**，产出却只是"哪几条可能有货 + 一句理由"——成本与产出严重不匹配；成本主因是推理 token（TRIGGER_PLAN §4.6 自己诊断过） |
| 分级压缩规则（命令行/stderr 放宽） | ✅ **采纳（新增）** | 一段式用压缩视图写卡片，损失的恰好是 sop/postmortem 的核心（完整命令、报错原文）。放宽小体积高价值部分、继续压 stdout，代价小而收益决定性 |
| 正文生成外包给 create-skill | ✅ **采纳** | 格式合规白送，省掉最机械的一环 |
| 选材/就绪门/description 约束也外包 | ❌ **拒绝** | 41 个技能 3 周只有 3 个被加载——**路由质量是生死线**。create-skill 不知道哪些卡短效、哪些跨会话复现、预算多少；选材与契约必须自研 |
| 文档先问用户再存 | 🔶 **部分采纳** | 直接采纳会漏（当时说不要，三个月后原文已不在）且打断心流；改为**按信号强度分档**：强信号直接存、中信号进批量确认卡、弱信号不动 |
| 砍掉覆盖水位 / 预算 / 锁 / 断点续跑 / 账本 | ❌ **拒绝** | 与几段式无关。一批调用失败或超预算时，没有这些就没法续跑、没法审计 |
| 砍掉 8 类型 | ❌ **拒绝** | 类型是把"整合时的重复判断"前移成"落库时的一次判断"。没有类型，每次整合都要重新理解每张卡是什么性质、能不能进正文、会不会过期——成本反弹 |
| 砍掉准入规则 | ❌ **拒绝** | 零 token 的代码校验，拦的是 45% 无来源 / 41% 自造类型名这类历史事故，性价比最高的一层 |

### 顺手砍掉的真·过度设计

1. **用推理模型单独跑一趟扫描**：TRIGGER_PLAN 内部曾自相矛盾——§4.6 诊断"成本主因是推理 token"、缓解措施写"用最低思考档位"，§十七 决议 1 又决定"保留推理模型"。**2026-11-11 收口：砍掉的是"独立扫描那一趟"，不是模型档位。** 一段式之后同一批内容只推理一遍，浪费从结构上就没了；再降档动的是抽取质量本身，而抽取质量是这条管线唯一的产出。档位维持推理模型，成本靠批次体积和 prompt 缓存去省。
2. **压缩抢救的独立子系统**（隔离区 + 摘要卡 + 专属转正流程）：为一个小概率事件建了一整套平行机制。可退化为"同一套流水线 + `trust=rescue` 标记 + 该批次进确认队列"。**待办，未实施。**
3. **校准工具里的正则遗留指标**（`hot_hit` / `cold_found`）：正则已退场、实验已完成、结论已入文档，这两个指标是死重量 → 随迁移归档删除。
4. **提案队列 + 文件锁双保险**：单用户本地工具，并发写技能场景很窄，留一套即可。**待评估。**

### 反过来，欠设计的两处（比简化更紧急）

1. **资料层只写不读**：index / data 卡片存了没有检索口 = 白存。
2. **drop 没记账**：漏检不可见。一段式已把它写进输出契约（`cards` 可空、`drops` 必有），随迁移一起补上。

### 抽取 ≠ 摘要（这次复盘最重要的认知）

一段式最大的风险是目标函数滑向 summary。两者的判据是相反的：

| | 摘要 | 知识抽取 |
|---|---|---|
| 求什么 | 覆盖（不漏要点、比例均衡） | 筛选（只留稀有的高价值信号） |
| 判据 | 重要不重要（≈原文篇幅与强调） | 三轴：稀缺性 / 验证性 / 复现性，任一为零即弃 |
| 丢弃率 | 越低越好 | 855 条只出 38 个候选（4%）是正常工作 |
| 失败模式 | 遗漏 | 灌水 |
| 时间指向 | 过去：这段说了什么 | 未来：下次遇到该怎么做 |

最尖锐的一条：对话里 99% 的体积是模型说的话，而"模型单独流畅生成的部分价值趋近于零"（EXTRACTION_PRINCIPLES §二）。**摘要的天然产物正好是抽取要排除的 P3。** 所以一段式的 prompt 必须写死反摘要禁令 + 反例 few-shot，验收必须有人工盲评摘要率（≤10%）。

设计里其实早已承认这个区别：压缩抢救的产物叫**摘要卡**，要隔离 + 人点一下才转正；短效知识转的历史记录文档是纯状态快照，明确**不进技能、不参与路由**。翻译过来就是——摘要是有用的产物，但它不是知识，不能拿去指导行动。

### 外部参照：billion-context（2026-11-11 复盘补充）

参考对象：`github.com/ranxianglei/billion-context`——坐在 coding agent 与模型 API 之间的压缩代理。其 `kernel/src/compression-rules.ts` 的提示词头注写明"数月生产调优、VERBATIM copy"，且 `prompts.ts` 宣称 "Every field here is LOAD-BEARING"：覆盖任何字段必须显式传 `{ acknowledgeRisk: true }`，否则 throw。

**场景只部分重叠**：它管的是**活会话的上下文窗口**（模型已经看过内容，压缩是为了省后续轮次）；我们是**离线从日志抽知识**（模型从没见过这些内容）。所以能抄的是"压缩什么、保留什么、怎么防摘要化"，不能抄的是"谁来触发压缩"。

**它验证了本方案的三个决策**：

| 我们的决策 | 它的证据 |
|---|---|
| 合并成一段式 | `ONE_CALL_HINT`（#2302）：555K 会话分 5 次调用 → 44 秒、**重复计费 1.38M tokens**；提示词写死 "never split the batch" |
| 压缩放宽 stderr / 完整命令 | `log-select` 硬约束："每条 ERROR/FAIL 行必须逐字存活，否则整体拒绝、原文透传" |
| drop 账 / 模型可否决 | #2228：模型答 `{"compress": false}` 即重置计数、**绝不 fallback**；"a real veto instead of an instruction with a checklist attached" |

**从它抄来的六条**（已分别落进 ONE_STAGE_EXTRACT §3.1.1 / §3.1.2 / §4.1 / §4.2 / §5.2.1 与本文 §三 / §四 / §五）：

1. 压缩 fail-safe 断言：报错行丢了，这条就不压、原样透传
2. 压缩占位符带取回凭证（msg_id + 类型 + 原始体积 + 命令），让按需回读有的放矢
3. 逐字保留清单：带行号的路径、签名、"就是结论的那行代码"、报错原文、精确数值、决策的 because
4. **引用是历史记录，不是活指令**（它的 #309 生产事故：伪造的用户原话被当成活体 CURRENT TASK，循环复发）
5. 正文-quote 重合度闸门（对应它的 net-benefit gate：摘要不比原文小就拒）
6. system prompt 字节级稳定以吃 prompt cache（它靠 append-only 拿到 94% 命中）

**架构同构**——说明这套分层不是过度设计，而是这类系统的收敛形状：

| billion-context | 本方案 |
|---|---|
| ccr（原文无损存 + 指针取回） | artifacts/ + index 登记卡 |
| crush（确定性机械压缩、零 token、fail-open） | 分级压缩规则 |
| absorb（模型蒸馏单个大工具结果，阈值 4000 tok） | 一段式抽取 |
| compress（区间摘要，nudge 触发，最小 5000 字符） | 技能编译（多卡合成） |
| emergency truncate（95% 安全阀） | 预算刹车（停在未审） |
| Tier3 "a lookup index, not a knowledge base" | index 登记卡 / 历史记录文档 |

**三条明确不抄**：

1. **"丢掉往复讨论和自我纠正，只保结论"**——对我们是砍掉最高价值：人纠正模型的那一刻是隐性偏好唯一显形的时机（P0），过程必须留
2. **模型自决压缩时机 + 折叠可展开**——那是活会话的上下文管理机制；我们离线抽取，必须由代码定规矩压好再喂
3. **"Work from summaries, not raw tool outputs"**——对我们正好相反：抽卡片必须看原文才能逐字接地（G1–G4），看摘要写卡就是 P3 自说自话
