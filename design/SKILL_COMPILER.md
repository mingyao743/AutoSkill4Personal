## 一、诊断：为什么默认路径必然产出知识快照

| 环节 | 现状 | 后果 |
|---|---|---|
| 选材 | 主题内知识卡片全量 | 短效项目状态混进正文 |
| 改写 | **没有这一步** | 知识卡片原文（含 atom_id/置信度）直接进 skill |
| 切分 | 按 15k 字符 | 小主题=堆砌，大主题=索引页；与"能否执行"无关 |
| 路由 | LLM 失败静默回退模板 | 40/41 无法被路由 |
| 精修 | agent 手动路径 | 全历史用了 2 次 |

一句话：**`package-skill` 是"排版器"，不是"编译器"。** 它假设上游已经有人把经验写成了操作指令，但上游只有知识卡片。

## 二、五条设计原则

1. **技能正文是编译产物，不是视图。** 卡片可以重建，技能必须被"写"出来。
2. **默认路径必须产出好技能。** 精修不能是可选路径，而是编译器输出之后的确认动作。
3. **路由是契约，必须可测。** description 不通过正负样本测试，就不许发布。
4. **切分按职责，不按体积。** 正文=决策程序（有预算），references=证据（无预算）。
5. **短效知识不进正文。** 项目进度、当前状态、本次结果 → 项目历史记录文档，不是技能。

## 三、新流水线

```
主题内 instruction 知识卡片
   │
   ├─ ① 就绪门：≥5 条、≥2 个会话、内容有变化（或 --force）
   │     └ 全短效知识 → 转文档，不编译
   │
   ├─ ② 选材：按"程序性 × 跨会话复现 × 新鲜度 − 短效度"排序
   │     ├ 正文预算内（≤6k 字）→ 进入正文
   │     └ 其余 → references（保留溯源）
   │
   ├─ ③ 编译（LLM，初始 + 最多 2 次重写）：知识卡片 → 结构化技能 draft
   │     输入：编译简报 + 选中卡片**完整**正文（简报里只截 400 字）+ create-skill 写法指引
   │     输出：`<briefDir>/<skill>.draft.md`；validate 不过 → 回喂 report.errors 重写，仍不过 → 保留 draft、不生成提案
   │
   ├─ ④ 规则校验（0 成本）：结构 / 去元数据 / 短效表述 / 长度 / 分诊条件
   │
   ├─ ⑤ 路由自测：正样本 ≥4/5 命中，负样本 ≤1/3 误命中
   │     不通过 → 带着失败原因重写描述（最多 2 次）→ 仍失败 → 阻断发布
   │
   ├─ ⑥ 质量关卡（可选 LLM judge）：删除测试 + 新人可执行性
   │
   └─ ⑦ 落盘：走提案队列（intake），由 applier 统一写
         已有 agent-maintained 技能 → 只提案不覆盖
```

## 四、SKILL.md 契约（可规则校验）

```markdown
---
name: <kebab-case>
description: <60–300 字，必须含 ≥3 个触发短语，禁止"领域知识库/由 AutoSkill 生成">
---

# <标题>

## 何时用
- <触发条件，来自知识卡片的 msg_range 场景>

## 判断
| 如果 | 那么 |
|---|---|
| <可观测现象> | <动作> |

## 步骤
1. <动作> → 核查：<checkpoint>
2. …

## 失败与回退
- <症状> → <根因> → <处置>

## 边界
- <环境/版本/先验>；失效条件：<…>

## 验证
- <怎么确认做成了>

## 何时读 references
| 你现在的处境 | 读这个 |
|---|---|
| <条件 1> | references/02-操作SOP.md |
| <条件 2> | references/05-问题与复盘.md |
```

不同 doc_type 的最小子集：

| 类型 | 必须有 |
|---|---|
| sop | 步骤 ≥3 且含失败与回退 |
| spec | 判断 ≥3 且含边界 |
| template | 步骤（填写流程）+ 骨架 |
| postmortem | 失败与回退 + 验证 |
| convention | 边界 + 失效条件 |
| rubric | 判断 ≥2 + 等级定义 |
| index | 分诊表（每行必须有条件）|

**机械禁止项**（出现即拒）：
- `atom_` / `置信度` / `状态 draft` / `来源 …` 等元数据
- 短效表述：`已实现` `本次` `今天` `M0`–`M3`（正文出现 ≥2 次即拒）
- 描述里的模板句式：`领域知识库` `由 AutoSkill` `涉及…时加载`
- 分诊表里没有条件的行（只列文件名不算）

## 五、路由自测（这是最关键的新东西）

编译时同时产出探针：

```json
{"probes": {
  "positive": ["机理标注跑完 gate 报 G4 条数不足怎么办", "…"],
  "negative": ["怎么用 Godot 做存档兼容", "…"]
}}
```

测试方式：把所有已编译技能的 description 放进一次 prompt，逐条问"这条请求会加载哪个技能"，要求：

- 正样本：目标技能排第 1，≥4/5
- 负样本：目标技能不排第 1，≥2/3
- 失败 → 把失败样例喂回描述生成器重写（最多 2 次）→ 仍失败则**阻断发布**

这一步把"路由"从发布后的运气，变成发布前的测试。成本：一次批量调用，按 description 集合 hash 缓存。

## 六、选材与预算

**入选排序**（确定性，不打分模型）：

```
score = 程序性(0/1) * 3
      + (sources.length ≥ 2 ? 2 : 0)      # 跨会话复现
      + 新鲜度(30 天内 2 / 90 天内 1 / 否则 0)
      + confidence
      − 短效表述命中(2) − 无 domain(3)
```

正文预算：**≤6000 字**，取排序靠前的条目；其余进 references。预算不足时**拆技能**（按任务族拆，不按 01–05 拆），而不是把正文压成目录。

## 七、短效知识（transient domain）与短效内容

**短效知识 = 整个主题的知识价值一起过期、没有可长期复用的核心。**

它不是"内容差"，而是"内容描述的是某一刻的状态"：谁在什么时候把什么改成了什么样、这次跑出了什么结果。这类内容编译成技能会变成**会过期的错误指令**——未来 agent 照着做，用的是三个月前的项目状态。

三个机械判据（任一命中即视为短效知识候选）：

1. **来源单一**：≥80% 知识卡片来自 compaction 抢救（`extracted_by=compaction-rescue`）——它天然只抓"刚才在干嘛"。（注：compaction 抢救通道已去掉，此判据仅对历史 atom 生效；新技能 rescueRatio→0 不触发，由判据 2/3 兜底）
2. **不可执行**：程序性标记（命令/步骤/脚本/检查）占比 <20%
3. **短效占比高**：短效表述（已实现/实施完成/当前/本次/M0–M3/状态）命中 ≥60%

实测符合的典型：

| 例子 | 为什么是短效 |
|---|---|
| 6 条无主题知识卡片 `M0/M1/M2/M3 实施事实` | 项目进度记录，三个月后即失真 |
| `autoskill-dsh-adapter`（100% 短效） | "我那天怎么接的"，不是"以后怎么接" |
| `game-design` / `gameplay-balance` / `game-rhythm-economy` | 程序性 0–17%、100% 压缩抢救、200–800 字，是一次讨论的碎片 |
| `godot-project-conventions` | 20% 程序性、100% 抢救，目录约定会变 |

反例（不是短效知识）：`gpu-train-ops` 的 OOM 排查——环境会变，但"先看显存再看容器、释放后要复测"这个动作序列长期成立。

**处置：短效知识不参与技能编译，只生成历史记录文档。**

| 内容 | 去向 |
|---|---|
| 可复现的动作/判断/口径 | 技能正文 |
| 短效知识的全部知识卡片 | 历史记录文档 `<domain>-current-state.md`（`keep_as=data` + `expires_when`），可审计、可检索，但**不进技能、不进路由** |
| 证据、案例、原文片段 | references（带溯源） |
| 一次性事务、可随时再生 | drop（errors.log 记账） |

**这不是删除，也不是永久判决**：知识卡片池不动；该主题后续若积累出程序性知识卡片（跨过就绪门），会自动"毕业"进入可编译状态。历史记录文档到期后按 `expires_when` 归档。

编译输出里的 `dropped[]` 必须写明理由，可审计。

> **实现偏差（2026-11-12）**：本文写“三个机械判据任一命中即视为短效知识候选”。实现时发现判据 2（程序性 <20%）对 spec / rubric 这类本来就非流程性的主题天然成立，单独命中就把主题判死会误杀。`compile-skill.ts` 改为要求 **≥2 条判据互相印证** 才判 short-lived（`TRANSIENT_BLOCK_HITS = 2`），单条只记 warning；`--force` 可强制编译。阈值集中在一个常量，实测有反例再调。

## 八、质量关卡

**机械（M，全部必须过）**
- M1 结构：必需段落齐全
- M2 可执行：步骤/判断条数达标
- M3 路由：正负探针通过

> M3 需要 LLM 或人工探针，`skill-contract.ts` **不假装做过**：只返回 `needsRoutingTest: true` 并在报告里标 ⏳。M3 由独立的 `--route-test` 落地（`lib/route-test.ts`）：正 ≥4/5、负 ≥2/3，失败回喂重写 description 最多 2 次，产物 `compile/<skill>.route.json`；`--apply` 读到**失败**报告必须拒绝（无报告/通过报告不拦，发布前必须补）。这是"确定性校验"和"质量结论"的分界线。
- M4 去噪：无元数据、无模板句式、短效表述 ≤1
- M5 预算：正文 ≤6000 字，分诊表每行有条件
- M6 引用闭合：分诊表引用的文件真实存在

**LLM judge（L，可选，失败不阻断但标记 `needs_review`）**
- L1 删除测试：正文每条非经验陈述，删掉后是否影响行动
- L2 新人可执行：只读正文能否完成一次任务

## 九、成本与增量

- 编译单位 = 主题；一次调用产出 body + description + 分诊 + 探针
- 缓存键 = `sha1(domain + atom_ids + prompt_version)`，命中直接跳过
- 路由测试按 description 集合批量做一次，按 hash 缓存
- 增量：新知识卡片 <20% 且已有技能 → 只重新编译受影响段落（v2）；v1 全量重编 + 提案 diff
- 预算护栏：`--limit N`、单次总输入上限、失败不重试超过 2 次
