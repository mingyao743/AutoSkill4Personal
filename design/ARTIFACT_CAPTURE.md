# 文档级知识捕获（ARTIFACT_CAPTURE）

> 术语 v2（2026-11-11 全库统一）：原子→知识卡片、机械闸门→准入规则、雷达/片段发现→抽取触发机制、提炼/片段抽取→知识抽取、瞬态域→短效知识、台账→历史记录；数据层命名不变（`atoms.jsonl`、`atom_*` 字段、`extracted_by=signal-distill` 仍指知识卡片）。本文正文已按新叫法书写。

> **⚠️ 决议更新（2026-11-11 晚）**：① 新增**抽取段**——收编之后对文档内容跑同一条流水线抽知识卡片（判重后只抽增量；blob 不抽，PII 风险；一份文档另配一张 index **登记卡**作户口）。② 触发按**信号强度分档**：强（明确意图"做成模板"）直接存 + 事后告知；中（写了文档 / 长结构化输出 / 粘贴大段）进批量确认卡；弱（只读过、无引用）不动。详见 STORE_OVERALL §五。

> 状态：proposed v2 · 2026-11-11
> 解决的问题：现有 `抽取触发机制 → 知识抽取` 只能产出"关于文档的判断"，产不出"文档本身"；一份 3000 字的方案在触发扫描里被压成首尾 500 字，结构在入口就丢了。
> 定位：与 claim 级管线**并列**的第二条入口。共享知识卡片池与准入，不共享触发与压缩。

## 一、先纠正一个错误切法

v1 把"agent 生成"和"agent 读"对立起来，这是错的。正确的切法是 **可重获性 × 价值形态**：

| 读来的资料 | 进入方式 | 存什么 |
|---|---|---|
| 支撑某个结论 | **证据** | 结论知识卡片 + `refs` 指针，不存原文 |
| 本身要被整体复用（外部模板/规范） | **素材** | 结构化缩减（骨架/规则），不是全文 |
| 以后还要找到它 | **导航** | `index` 知识卡片（位置 + 用途 + 失效条件） |

**信号修正**：读本身不是信号，**被引用/被复述/被依赖才是信号**。
agent 读 50 个文件不是知识；它在结论里引用了其中一段，那一段才是。

网页同理：不存全文（版权 + 易变），但**存"切片 + 出处 + 抓取日期"是合理的**，不再一刀切排除。

## 二、三种落库形态（blob 降级为例外）

| 形态 | 适用 | 大小 | 存什么 |
|---|---|---|---|
| **结构化缩减**（skeleton） | 模板、方案、报告 | 原文 10–30% | 标题树 + 占位符 + 关键决策 + 约束 |
| **切片**（slice） | 读到的规范/事实 | 每条 ≤200 字 | 主张 + 出处 + 日期 + 适用条件 |
| **原文 blob** | 不可重获且不可结构化 | 100% | 客户原始表格、扫描件、已下线资料 |

默认走前两种；blob 只在"删了就永久丢"时使用，且必须 PII 准入规则 + 人确认。

**为什么不能只切片**：模板/方案的价值在整体结构（章节顺序、字段、占位符），切碎就没了 → 用"结构化缩减"保留结构、去掉填充。
**为什么不能只存全文**：存储、版权、检索成本；下次 agent 还得读全文 → 用"切片 + 指针"。
**为什么不能删 blob**：不可重获又无法结构化的材料，切了就永久丢 → 兜底保留。

## 三、触发：结构信号 + 引用信号（零 LLM）

每轮结束后扫描新消息：

| 信号 | 判定 | 产物 |
|---|---|---|
| 写文档 | `write/edit/create`，路径命中 `docs/ design/ templates/ reports/` 或 `.md/.docx/.xlsx/.pptx`，内容 >1500 字 | 结构化缩减 |
| 长结构化输出 | 单条 assistant >2500 字且结构分 ≥3（标题/表格/代码块/编号列表） | 结构化缩减 |
| 用户粘贴 | 单条 user >1500 字且带结构 | 结构化缩减 / data |
| 明确意图 | "生成一份 / 做成模板 / 以后都按这个格式" | 结构化缩减 |
| **引用** | 结论消息里有引用块 `>`、带路径的行内代码、或关键术语与某段资料强重合 | **切片** |
| 重复阅读 | 同一文件/URL 在 ≥2 个会话被读，且结论引用了它 | 切片升级为素材 |

**不做**：给所有读过的资料建索引（噪音）；把网页抓取结果整篇存下来（版权）。

## 四、切片怎么定义（由使用定义，不由文档边界定义）

> 切片 = **被结论引用/复述的最小单元**，不是固定 500 字一块。

三种识别方式，按可靠性排序：

1. **显式引用**：assistant 消息含 `>` 引用块、或 `path:line` 形式的内联代码 → 取引用内容 + 出处
2. **语义重合**：结论消息的关键术语与某段资料重叠度高 → 取重叠段落（可选用一次小模型判定）
3. **人工选择**：待确认卡片里，人勾选"这段值得留"

每条切片必须带：`source`（路径/URL）、`line_range` 或 `section`、`retrieved_at`、`expires_when`。
切片总长 ≤200 字；超了就说明它其实是"素材"，走结构化缩减。

## 五、结构化缩减怎么做

不是 LLM 自由摘要，而是**结构保留、填充删除**：

| 文档类型 | 保留 | 删除 |
|---|---|---|
| 模板 | 标题树、字段名、占位符、必填标记、格式说明 | 示例正文、寒暄 |
| 方案 | 标题树、目标、被否方案、决策与理由、风险 | 论证过程、重复表述 |
| 报告 | 标题树、结论、数据口径、图表说明 | 过程流水 |

做法：markdown 解析（标题/表格/占位符）+ 规则裁剪；需要语义判断时用一次小模型（约 2k token）。
缩减结果进知识卡片字段（`skeleton` / `outline` / `decisions`），**不存整篇**。

## 六、存储

```
knowledge/
  artifacts/<sha256前16>.md     # 仅 blob 形态：不可重获且不可结构化的原文
  atoms.jsonl                   # 结构化缩减 / 切片 / blob 索引
```

知识卡片新增字段：

| 字段 | 说明 |
|---|---|
| `artifact_form` | `skeleton` / `slice` / `blob` |
| `artifact_ref` | blob 文件名（仅 blob 形态） |
| `artifact_hash` / `artifact_bytes` | 哈希与大小（三种形态都记，便于版本比对） |
| `outline` | 标题树（≤20 项） |
| `source` | 路径 / URL / 消息 id |
| `retrieved_at` | 取回时间（外部资料必填） |
| `expires_when` | 失效条件 |

**单一事实源不变**：知识卡片是"这是什么、为什么留"的事实源；blob 只是不可缩减时的载荷。

## 七、判型与去向

| 判定 | 依据 | doc_type | 去向 |
|---|---|---|---|
| 模板 | ≥2 个占位符，或 ≥3 标题 + 字段式标签 | `template` | 平台文档层 |
| 案例/方案 | 含背景/目标/方案/结果/风险章节 | `case` | 平台文档层 |
| 规范 | 含"必须/禁止/口径/判定" | `spec` | 平台文档层 |
| 客户资料 | 用户提供 + PII/内部域名 | `data` | 资料层（脱敏） |
| 外部资料切片 | 有出处、≤200 字 | `spec` / `index` | 技能正文或依据区 |

## 八、确认：人确认产物

- artifact 进"待确认卡"，不直接进技能
- 卡片展示：标题 / 形态 / 类型 / 字数 / 大纲 / 摘要 / 来源 / 风险标记
- 确认后：进平台文档层（prepare/commit），技能正文生成指针
- 与抢救摘要卡复用同一通道：**人确认产物，不确认知识卡片**

## 九、去重与版本

| 场景 | 处理 |
|---|---|
| 同哈希 | 跳过 |
| 同路径、内容变了 | 新知识卡片 + `supersedes`，旧版 deprecated |
| 同一文档既出 artifact 又出 claim | 允许；claim 的 `refs` 指向 artifact id |
| 切片重复 | 按 内容哈希 + 出处 去重 |

## 十、与 claim 管线的关系

- **共享**：知识卡片池、8 类型、PII 准入规则、确认通道、平台发布
- **不共享**：触发（结构/引用 vs 语义）、压缩（结构化缩减 vs 500/500）、单位（整份/切片 vs 一条判断）
- **互不阻塞**：artifact 检测零成本，可每轮跑；claim 仍按 待审 ≥30 条 或 ≥12k token 节流（时间下限已取消）
- **水位**：`reviewed.jsonl` 只管 claim；artifact 用哈希去重

## 十一、成本

| 形态 | 检测 | 生成 | 确认 |
|---|---|---|---|
| 结构化缩减 | 0 | 0（规则）/ 2k token（语义冲突时） | 一次点击 |
| 切片 | 0 | 0（引用提取）/ 可选 1k token | 批量确认 |
| blob | 0 | 0（读盘） | 一次点击 |

对比 claim 管线：一份 3000 字方案会被切成 5–10 条知识卡片、约 15k token，还丢结构。

## 十三、验收

1. 写 3k 字模板到 `docs/` → 1 条 `template`（`artifact_form=skeleton`），大纲与占位符正确，**不存全文**
2. assistant 引用某文档一段并下结论 → 1 条 `slice`，带出处与日期，≤200 字
3. 同一模板改一版 → `supersedes`，旧版 deprecated
4. 抓网页 → 只可能产生 slice，不产生 blob
5. 客户原始表格 → `blob` + `data` + 脱敏 + 人确认
6. 编译器只引用指针，不把模板正文塞进 SKILL.md

## 十四、待决策

1. **默认形态**：我建议"结构可识别 → 缩减；有引用 → 切片；否则不存"，blob 只在人工确认后启用。
2. **切片确认**：批量确认（一次勾多条），还是逐条？
3. **外部网页切片**：允许存 ≤200 字 + 出处，还是只存摘要？我建议允许，但必须在卡片上标来源与日期。
4. **blob 保留期**：确认丢弃后保留 7 天可复原，还是立即删？
